# [FR-08][Bug] `shipping_address` không được validate — chấp nhận rỗng, null, khoảng trắng và thiếu trường

**Labels:** `bug`, `FR-08`, `black-box-testing`, `severity: high`

---

## 1. Tóm tắt (Summary)

Endpoint `POST /api/checkout` không thực hiện bất kỳ validation nào đối với trường `shipping_address`. Backend chấp nhận tất cả các giá trị không hợp lệ (chuỗi rỗng `""`, `null`, khoảng trắng `" "`, và hoàn toàn không gửi trường này) và vẫn trả về `200 OK`, tạo đơn hàng thành công. Điều này vi phạm nghiệp vụ cơ bản: cần có địa chỉ giao hàng để thực hiện vận chuyển.

---

## 2. Nguồn spec / kỳ vọng (Expected Behavior)

- **Tài liệu tham chiếu:** `contexts/README.md` — FR-08 §2, dòng 102–108; `contexts/api_specification.md` §4.3, dòng 135
- **Trích nội dung spec:**
  > "Phải cung cấp địa chỉ giao hàng hợp lệ." và trường `shipping_address` được liệt kê là bắt buộc trong API body.
- **Mức độ rõ ràng của spec:** `[Giả định hợp lý — CẦN XÁC NHẬN]` — spec nêu "địa chỉ giao hàng" nhưng không chỉ rõ validation cụ thể. Tuy nhiên, nghiệp vụ giao hàng đòi hỏi địa chỉ phải có nội dung thực.

## 4. Các bước tái hiện (Steps to Reproduce)

### Test case TC-D2 — Chuỗi rỗng:
1. Đăng nhập với user có giỏ hàng chứa sản phẩm.
2. Gửi request `POST /api/checkout`:
   ```json
   {
     "shipping_address": ""
   }
   ```
3. Quan sát response: `200 OK` với `orderId: 7` — checkout thành công dù địa chỉ rỗng.

### Test case TC-D3 — Null:
1. Gửi request `POST /api/checkout`:
   ```json
   {
     "shipping_address": null
   }
   ```
2. Quan sát response: `200 OK` với `orderId: 8` — checkout thành công dù địa chỉ null.

### Test case TC-D4 — Khoảng trắng:
1. Gửi request `POST /api/checkout`:
   ```json
   {
     "shipping_address": "   "
   }
   ```
2. Quan sát response: `200 OK` với `orderId: 9` — checkout thành công dù địa chỉ chỉ có khoảng trắng.

### Test case TC-D5 — Thiếu trường:
1. Gửi request `POST /api/checkout`:
   ```json
   {}
   ```
2. Quan sát response: `200 OK` với `orderId: 10` — checkout thành công dù không gửi trường `shipping_address`.

**Môi trường test:** Local, công cụ: Postman

## 5. Giả thuyết hành vi (Behavioral Hypothesis)

> Đây là suy luận **black-box động** (dynamic behavioral inference) dựa trên quan sát qua API, không phải đọc source code.

- **Giả thuyết:** Backend hoàn toàn không có middleware hoặc logic validation cho trường `shipping_address`. Có thể:
  - Backend không kiểm tra `isset()` hoặc `!empty()` cho trường này.
  - Trường `shipping_address` trong bảng `orders` cho phép NULL hoặc default value mà không có constraint.
  - Không có `required` validation ở API layer.
- **Mức độ tin cậy:** `Cao` — cả 4 test case đều cho kết quả rõ ràng: backend không validate gì cả.
- **Test case bổ sung cần chạy để xác nhận:**
  - Kiểm tra xem đơn hàng được tạo có lưu giá trị `null`/`""` trong CSDL không hay backend tự động set default.
  - Kiểm tra xem bên shipper có nhận được địa chỉ giao hàng không.
