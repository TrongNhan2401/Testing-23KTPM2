# [FR-16][Bug] Backend không enforce max length 255 cho `name` — chấp nhận name với hơn 255 ký tự

**Labels:** `bug`, `FR-16`, `black-box-testing`, `severity: high`

---

## 1. Tóm tắt (Summary)

Endpoint `POST /api/admin/import-products` không enforce giới hạn độ dài tối đa 255 ký tự cho trường `name`. Sản phẩm với tên dài 256 ký tự vẫn được chấp nhận và thêm vào hệ thống. Điều này vi phạm FR-15: "Tên sản phẩm: bắt buộc, tối đa 255 ký tự."

---

## 2. Nguồn spec / kỳ vọng (Expected Behavior)

- **Tài liệu tham chiếu:** `contexts/README.md` — FR-15 §2, dòng 195; FR-16 §2, dòng 208
- **Trích nội dung spec:**
  > "Tên sản phẩm: bắt buộc, tối đa 255 ký tự." (FR-15)
  > "`name` không được rỗng." (FR-16)
- **Mức độ rõ ràng của spec:** `[Rõ ràng từ spec]` — spec nêu rõ max length = 255 ký tự.

---

## 3. Hành vi thực tế quan sát được (Actual Behavior)

| Bước | Input | Expected | Actual | Status |
|---|---|---|---|---|
| 1 | Body: `{ products: [{ name: "A"*256, price: 100000, category_id: 1 }] }` | `400` — name vượt quá 255 ký tự, rollback | `200 OK` `{ "message": "Import hoàn tất: 1/1 sản phẩm được thêm", "inserted": 1, "errors": [] }` | ❌ |
| 2 | Kiểm tra `GET /api/products/:id` | Name chỉ chứa 255 ký tự hoặc bị từ chối | Sản phẩm được thêm với name đầy đủ 256 ký tự | ❌ |

---

## 4. Các bước tái hiện (Steps to Reproduce)

1. Đăng nhập với tài khoản admin.
2. Gửi request `POST /api/admin/import-products`:
   ```json
   {
     "products": [
       {
         "name": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
         "price": 100000,
         "category_id": 1
       }
     ]
   }
   ```
   (chuỗi 256 ký tự "A")
3. Quan sát response: `200 OK` — sản phẩm được thêm thành công.
4. Gọi `GET /api/products/:id` để xác nhận name được lưu đầy đủ 256 ký tự.

**Môi trường test:** Local, công cụ: Postman

---

## 5. Giả thuyết hành vi (Behavioral Hypothesis)

> Đây là suy luận **black-box động** (dynamic behavioral inference) dựa trên quan sát qua API, không phải đọc source code.

- **Giả thuyết:** Backend không kiểm tra độ dài của `name` trước khi insert vào CSDL. Có thể trường `name` trong bảng `products` được định nghĩa là `VARCHAR(255)` nhưng không có validation ở tầng application.
- **Mức độ tin cậy:** `Cao` — quan sát rõ ràng: sản phẩm được thêm với name 256 ký tự.
- **Test case bổ sung cần chạy để xác nhận:**
  - Test với name 255 ký tự (BV-N2) — xác nhận đây là boundary đúng.
  - Kiểm tra CSDL xem trường `name` có kiểu VARCHAR(255) hay TEXT không.

## 6. Mức độ ảnh hưởng (Severity/Priority)

- **Severity:** `High`
- **Lý do:**
  - Vi phạm spec FR-15: max length 255 ký tự.
  - Có thể gây ra vấn đề hiển thị trên UI (layout break).
  - Có thể gây ra vấn đề lưu trữ nếu DB column là VARCHAR(255) — lưu trữ không nhất quán.
  - Nên có validation ở cả tầng application và database.
