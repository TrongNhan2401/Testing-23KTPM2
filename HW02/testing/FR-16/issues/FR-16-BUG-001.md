# [FR-16][Bug] User thường (non-admin) có thể import sản phẩm — vi phạm FR-12 Access Control

**Labels:** `bug`, `FR-16`, `black-box-testing`, `severity: critical`

---

## 1. Tóm tắt (Summary)

Endpoint `POST /api/admin/import-products` cho phép user thường (có JWT token với `role = 'user'`) gửi request import sản phẩm và nhận response thành công (`200 OK`), sản phẩm được thêm vào hệ thống. Điều này vi phạm nghiêm trọng FR-12 Access Control: chỉ tài khoản admin mới được phép thực hiện thao tác import.

---

## 2. Nguồn spec / kỳ vọng (Expected Behavior)

- **Tài liệu tham chiếu:** `contexts/README.md` — FR-12 §2, dòng 174–180
- **Trích nội dung spec:**
  > "Phân hệ Admin chỉ dành cho tài khoản có `role = 'admin'`. Tất cả các API Admin (`/api/admin/*`) và các API có tính ảnh hưởng dữ liệu đều phải yêu cầu: 1. Token JWT hợp lệ. 2. `role = 'admin'` trong Token."
- **Mức độ rõ ràng của spec:** `[Rõ ràng từ spec]` — đây là yêu cầu bắt buộc về phân quyền.

## 3. Hành vi thực tế quan sát được (Actual Behavior)

| Bước | Input | Expected | Actual | Status |
|---|---|---|---|---|
| 1 | Gửi `POST /api/admin/import-products` với JWT của user thường (role = 'user') | `403 Forbidden` — không có quyền import | `200 OK` `{ "message": "Import hoàn tất: 1/1 sản phẩm được thêm", "inserted": 1, "errors": [] }` | ❌ |
| 2 | Kiểm tra `GET /api/products` | Không thấy sản phẩm mới được thêm bởi user thường | Sản phẩm được thêm thành công vào hệ thống | ❌ |

## 4. Các bước tái hiện (Steps to Reproduce)

1. Đăng nhập với tài khoản user thường (role = 'user') — ví dụ: `test@eshop.com` / `Test1234!`.
2. Lấy JWT token từ response đăng nhập.
3. Gửi request `POST /api/admin/import-products` với header:
   ```
   Authorization: Bearer <user_token>
   ```
   và body:
   ```json
   {
     "products": [
       {
         "name": "Sản phẩm test",
         "price": 100000,
         "category_id": 1
       }
     ]
   }
   ```
4. Quan sát response: `200 OK` — sản phẩm được thêm thành công.
5. Gọi `GET /api/products` để xác nhận sản phẩm đã được tạo.

**Môi trường test:** Local, công cụ: Postman

---

## 5. Giả thuyết hành vi (Behavioral Hypothesis)

> Đây là suy luận **black-box động** (dynamic behavioral inference) dựa trên quan sát qua API, không phải đọc source code.

- **Giả thuyết:** Backend không kiểm tra trường `role` trong JWT token khi xử lý `POST /api/admin/import-products`. Có thể backend chỉ kiểm tra token tồn tại và hợp lệ, nhưng bỏ qua bước kiểm tra `role = 'admin'`. Điều này vi phạm SEC-03: "API Admin phải kiểm tra `role = 'admin'` trong Token, không chỉ kiểm tra sự tồn tại của Token."
- **Mức độ tin cậy:** `Cao` — quan sát rõ ràng: user thường import thành công.
- **Test case bổ sung cần chạy để xác nhận:**
  - Test các endpoint admin khác (`POST /api/admin/coupons`, `DELETE /api/admin/categories/:id`) với user thường — xem có cùng bug không.

## 6. Mức độ ảnh hưởng (Severity/Priority)

- **Severity:** `Critical`
- **Lý do:**
  - Vi phạm nghiêm trọng nguyên tắc phân quyền (Authorization).
  - Bất kỳ user nào cũng có thể import sản phẩm, thay đổi dữ liệu kinh doanh.
  - Có thể khai thác để thêm sản phẩm giả/mạo danh vào hệ thống.
  - Vi phạm SEC-03 trong Security Requirements.
