# [FR-04][Bug] Backend cho phép thay đổi `role` của chính mình — vi phạm nghiêm trọng FR-04 Access Control

**Labels:** `bug`, `FR-04`, `black-box-testing`, `severity: critical`, `security`

---

## 1. Tóm tắt (Summary)

Endpoint `PUT /api/users/me` cho phép người dùng thường (role = 'user') thay đổi trường `role` của chính mình thành 'admin'. Điều này vi phạm nghiêm trọng FR-04: "Người dùng chỉ có thể cập nhật hồ sơ của chính mình; không thể tự thay đổi thuộc tính `role`."

## 4. Các bước tái hiện (Steps to Reproduce)

### Test case TC-E2 — Thay đổi role:
1. Đăng nhập với tài khoản user thường (role = 'user').
2. Lấy JWT token từ response đăng nhập.
3. Gửi request `PUT /api/users/me` với body:
   ```json
   {
     "name": "Test User",
     "role": "admin"
   }
   ```
4. Quan sát response: `200 OK` — hồ sơ được cập nhật.
5. Gọi `GET /api/users/me` để xác nhận: **role đã bị thay đổi từ 'user' thành 'admin'**.

**Môi trường test:** Local, công cụ: Postman

---

## 5. Giả thuyết hành vi (Behavioral Hypothesis)

> Đây là suy luận **black-box động** (dynamic behavioral inference) dựa trên quan sát qua API, không phải đọc source code.

- **Giả thuyết:** Backend không filter trường `role` khi nhận request update profile. Backend cập nhật tất cả các trường được gửi trong body, bao gồm cả `role`. Điều này vi phạm nghiêm trọng security: user có thể tự nâng quyền thành admin.
- **Mức độ tin cậy:** `Cao` — quan sát rõ ràng: role đã bị thay đổi.
- **Test case bổ sung cần chạy để xác nhận:**
  - Test xem sau khi thay đổi role, user có thể truy cập các API admin không.
  - Test xem user có thể thay đổi role về 'user' không.
